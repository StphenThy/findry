# Deploying Findry (free tiers)

Three pieces: **MongoDB Atlas** (database) → **Render** (Express API) → **Vercel** (React client).
Everything deploys from a GitHub repo, so push the project first.

```
Browser ──► Vercel (client/dist) ──► Render (server) ──► Atlas (MongoDB)
```

## 1. MongoDB Atlas

1. https://www.mongodb.com/atlas → create a free account → **Build a Database** → **M0 Free**.
2. Region: Singapore (closest to PH). Create a database user (username + password — no special characters to avoid URL-encoding issues).
3. **Network Access** → Add IP → `0.0.0.0/0` (Render's IPs change).
4. **Connect** → Drivers → copy the URI and replace `<password>`:
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/findry?retryWrites=true&w=majority`
5. (Optional) seed it from your machine:
   ```bash
   # server/.env → MONGODB_URI=<the URI above>
   npm run seed          # or: npm run seed -- --force   to reset
   ```
   In development the server seeds automatically on first boot when the DB is empty (`SEED_ON_START=true`).

   > **Demo data and production.** The demo accounts use a password that is printed in this repo, so the
   > production server never seeds them (unless `SEED_DEMO_IN_PROD=true`) and refuses to sign in any `*.demo`
   > account. If your live database was seeded earlier, remove the demo users, jobs and applications with:
   > ```bash
   > npm run purge-demo -w server -- --dry-run   # preview
   > npm run purge-demo -w server               # delete
   > ```

## 2. Gemini API key (free)

https://aistudio.google.com → **Get API key** → create. No card required. If you skip this, the app still works with the built-in `local` parser.

## 3. Render — the API

1. https://render.com → **New +** → **Blueprint** → connect the GitHub repo. Render reads `render.yaml`.
   (Or **New + → Web Service** manually: Root Directory `server`, Build `npm install --include=dev && npm run build`, Start `npm start`, Health check `/api/health`.)
2. Fill in the environment variables it asks for:

   | Key              | Value                                              |
   | ---------------- | -------------------------------------------------- |
   | `MONGODB_URI`    | the Atlas URI                                      |
   | `CLIENT_URL`     | your Vercel URL (add after step 4, e.g. `https://findry.vercel.app`) |
   | `GEMINI_API_KEY` | the key from step 2 (or leave empty)               |
   | `JWT_SECRET`     | auto-generated by the blueprint                    |
   | `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` | **required** — password reset answers 503 without them, and signup email verification (6-digit code) only switches on once these are set (Gmail app password, Resend, Brevo, etc.) |

3. Deploy. Your API is at `https://findry-api.onrender.com/api/health`.

> **Free-tier note:** Render spins the service down after ~15 min idle; the first request afterwards takes 30–60 s. Open the API URL a minute before a demo. Uploaded resume files live on an ephemeral disk — the parsed text and skills are stored in MongoDB, so nothing user-visible is lost.

## 4. Vercel — the client

1. https://vercel.com → **Add New → Project** → import the repo.
2. **Root Directory**: `client`. Framework preset: Vite (auto-detected). Build `npm run build`, output `dist`.
3. **Environment Variables**: `VITE_API_URL` = `https://findry-api.onrender.com` (no trailing slash).
4. Deploy. `client/vercel.json` already contains the SPA rewrite so deep links like `/seeker/jobs/123` work on refresh.
5. Go back to Render and set `CLIENT_URL` to the Vercel URL (CORS). Redeploy the API.

Every `git push` to `main` redeploys both.

## Alternative: single server (one URL, no CORS)

Have Express serve the built client — simpler for a demo, but the frontend also suffers the cold start.

- Render Web Service with **Root Directory** = repo root, Build `npm install --include=dev && npm run build`, Start `npm start`.
- Env: `SERVE_CLIENT=true`, `CLIENT_URL=https://<your-render-url>`, plus the DB/AI vars above.
- Skip Vercel entirely.

## Local production check

```bash
npm run build
SERVE_CLIENT=true npm start        # PowerShell: $env:SERVE_CLIENT='true'; npm start
# → http://localhost:4000 serves the client and the API together
```

## Troubleshooting

| Symptom                                   | Fix                                                                           |
| ----------------------------------------- | ----------------------------------------------------------------------------- |
| Build fails with `tsc: not found`          | `NODE_ENV=production` makes npm skip devDependencies — the build command must be `npm install --include=dev && npm run build`. |
| `Origin … not allowed by CORS`            | Add the exact client origin (scheme + host, no path) to `CLIENT_URL` on Render. |
| `MongoServerSelectionError` on Render     | Atlas Network Access must include `0.0.0.0/0`; check the URI password.         |
| Login works locally, 401 on Vercel        | `VITE_API_URL` missing/incorrect — it's a **build-time** var, redeploy after changing. |
| Gemini errors in logs                     | Free-tier rate limit hit; the app falls back to the local parser automatically. |
| Resume upload returns 422                 | Scanned/image PDF — export a text-based PDF or DOCX.                           |
